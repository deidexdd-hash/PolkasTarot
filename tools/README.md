# Инструменты

Сам сайт статический и ничего не собирает — здесь лежит только то, чем его
проверяют. `package.json` намеренно стоит в этой папке, а не в корне: иначе
хостинг может принять статический сайт за Node-проект и начать его собирать.

```
npm --prefix tools install      # один раз
```

## js2json.js — данные

Собирает `data/*.json` из исходников `js/data/*.js` и проверяет их.

```
node tools/js2json.js               собрать выгрузку
node tools/js2json.js --check       только проверить, ничего не писать
node tools/js2json.js --fix-source  ещё и переписать js/data/*.js
node tools/js2json.js --csv         дополнительно выгрузить data/cards.csv
```

`--check` падает, если данные невалидны (не 78 карт, дубли id, нет файла
картинки) **или** если исходники требуют починки. Второе важнее: конвертер
чинит копию в памяти, а браузеру достаётся файл как есть. Этот же вызов
крутится в CI.

## e2e.js — приложение целиком

Поднимает `index.html` в jsdom, подменяет `fetch` чтением файла и проверяет
то, что видит пользователь: колода, галерея, карточка, расклад.

```
node tools/e2e.js                    обычный прогон
node tools/e2e.js --broken-storage   localStorage бросает на каждый вызов
```

Второй режим воспроизводит приватный режим браузера и запрет данных сайта.
Колода обязана загрузиться и там: однажды исключение из `localStorage`
роняло загрузку целиком, и нашлось это именно так.

## audit.js — вёрстка на телефоне

Открывает страницу в настоящем Chromium с экраном iPhone и ищет то, чего не
видно ни на скриншоте, ни в коде: элементы за краем экрана, слишком мелкие
кнопки, перекрытые элементы.

Нужен сервер: приложение читает `data/cards.json` через `fetch`, а с `file://`
браузер это запрещает.

```
python3 -m http.server 8777     # в отдельном окне, из корня репозитория
node tools/audit.js
```

Так нашлись две вещи, незаметные глазом: кнопка закрытия карточки, накрытая
липкой шапкой, и первая плашка ленты, которую `scroll-snap` притягивал к краю,
съедая отступ.

## fetch-images.js — картинки и их происхождение

Заменяет 78 картинок колоды сканами с Викисклада и записывает происхождение
каждой в `SOURCES.md`.

```
node tools/fetch-images.js --dry-run    только проверить имена и лицензии
node tools/fetch-images.js              проверить, скачать, заменить
node tools/fetch-images.js --width 900  другой размер по длинной стороне
```

Зачем это нужно, написано в [`SOURCES.md`](../SOURCES.md): у нынешних файлов
происхождение не установлено, а без него проект нельзя лицензировать.

Скрипт не берёт лицензию на веру и не проставляет её сам: он читает её из
ответа Викисклада для каждого файла и отказывается качать всё, если хоть один
файл не оказался общественным достоянием.

Размер он тоже проверяет по факту, а не по обещанию: у скачанного файла
читается ширина из заголовка JPEG. Викисклад умеет отдать под видом
уменьшенной копии оригинал — один такой прогон дал колоду в 40 МБ вместо
трёх, при том что в шапке честно стояло «ширина 720 px». Теперь адрес
уменьшенной копии в таком случае собирается заново, а если и это не
помогло — прогон падает с внятным сообщением.

Имена файлов он тоже не считает истиной. Если карта не нашлась, скрипт
смотрит, в каких категориях лежит карта, которая нашлась, перебирает файлы
оттуда и подставляет найденное имя — но только когда кандидат ровно один.
Два похожих имени это уже лотерея, и выбирать за человека там нельзя: такая
карта остаётся в списке ошибок вместе с вариантами. Все подстановки
печатаются, и в `SOURCES.md` попадает то имя, которое действительно
скачано. Замена атомарная — файлы едут в
`img/cards` только когда скачаны все 78, так что колода не окажется наполовину
одной, наполовину другой.

Нужен доступ к `commons.wikimedia.org`. HTTP 403 на `api.php` почти всегда
значит, что запрос не выпустили наружу (прокси, корпоративная сеть,
песочница), а не что Викисклад отказал.

**Если запускать негде.** У раннера GitHub интернет есть: вкладка Actions ->
«Картинки» -> Run workflow. По умолчанию стоит только проверка; снимите
галочку «Только проверить», чтобы он скачал картинки, прогнал проверки
колоды и открыл PR с результатом. Хостинг вроде Render тут ни при чём — он
раздаёт готовые файлы из репозитория и этот скрипт никогда не запускает.

Проверить логику скрипта, не трогая настоящий Викисклад, можно подсунув свой
адрес API:

```
COMMONS_API=http://127.0.0.1:8899/w/api.php node tools/fetch-images.js
```

## screenshots.js — снимки экранов

Телефон и настольный размер, светлая и тёмная темы, карточка свёрнутая и
раскрытая. Складывает в `screenshots/` (в репозиторий не попадает).

```
python3 -m http.server 8777
node tools/screenshots.js
```

## Если браузер не находится

`audit.js` и `screenshots.js` берут Chromium, который поставил playwright.
Когда в системе уже есть своя сборка, путь к ней задаётся переменной:

```
CHROMIUM_PATH=/путь/к/chrome node tools/audit.js
```
